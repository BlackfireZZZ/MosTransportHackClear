# Сильные ориентиры и слабые совпадения

Данные: 15.05.2025, Europe/Moscow. Три прежние группы валидаторов, гипотеза clock_terminal180, продолжение с весом абсолютного отклонения0, без дополнительного допуска после конечной. В графике сохранён полный диапазон записей с10-минутным продолжением. Выбранный рейс и позиции сильных начал зафиксированы; новые пары их не переоценивают. Слабые кандидаты взяты из прежнего small-stops-data.json, исходные оплаты не изменяются.

Ожидаемое время каждой остановки вычисляется от предыдущего сильного начала: его фактическое время плюс интервал расписания между позициями. Для самого сильного начала показано ожидание от предшествующего ориентира; после него сдвиг обновляется. Первый ориентир задаёт начальный сдвиг. Слабые события никогда не меняют ожидаемые времена, даже после успешного сопоставления. Граница последнего наблюдаемого сильного события не является границей рейса; отсутствие оплаты на конечной допустимо.

Матчинг выполняется динамическим программированием по упорядоченным остановкам и кандидатам. Сначала максимизируется число пар в пределах выбранного допуска15/30/45/60/90с, затем минимизируется сумма абсолютных отклонений. Нельзя повторно использовать остановку или волну оплат, нарушать порядок либо пересекать следующий сильный ориентир поддержкой слабого кандидата. Пересекающиеся интервалы поддержки кандидатов образуют компоненты альтернативных начал одной волны: каждой компоненте разрешена максимум одна пара. Альтернативные начала уже выбранной волны скрыты на графике, исходный пул сохранён в JSON. Это консервативная защита от дробления; близкие реальные посадки с перекрывающимися поддержками остаются неразрешимыми этой проверкой.

Допуски не подбирались для достижения заранее заданной полноты. При±30с дополнительные пары:17=3,12=4,11=5; при±60с:17=7,12=7,11=9. Это максимум условных совпадений при замороженной гипотезе, не измеренная точность stop_id. Правая соседняя сильная отметка ограничивает диапазон кандидатов; её время не используется для подстройки ожидаемого слабого события задним числом.

Проверки build-anchor-matching.py: контрпример для жадного ближайшего сопоставления; запрет двух пар внутри одной перекрывающейся волны, включая цепочку альтернативных коротких поддержек; нулевой допуск без совпадений; уникальность, порядок и допуск всех реальных пар; неубывание числа пар с ростом допуска; инвариантность к общему сдвигу времени420с. Всего15реальных конфигураций. Браузер подтвердил изменение числа пар7→3 при неизменных координатах всех синих линий маршрута17.

Воспроизведение: python3 build-anchor-matching.py из этой папки. Вход, скрипт и результат связаны SHA256 в anchor-matching-manifest.json. Данные — anchor-matching-data.json, визуализация — tram-anchor-matching.html. Production-код, обучение, первичные данные и зависимости не менялись.
