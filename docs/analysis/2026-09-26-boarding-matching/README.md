# Посадки, сильные ориентиры и слабые совпадения

Это продолжение [аудита абсолютного времени](../2026-09-26-absolute-clock/README.md).
Сохранены код диагностических прогонов, агрегированные результаты и все графики
из обсуждения. Исходные оплаты, идентификаторы пассажиров, GTFS ZIP и обучающие
выгрузки сюда не включены. Эти результаты не являются подтверждёнными метками
остановок и не подключены к production-прогнозам.

## Что открыть

- [Сопоставление сильных и слабых начал](matching-preview.html) — самостоятельный
  HTML: скачать и открыть в браузере. Красные ориентиры сдвигают последующее
  расписание; слабые отметки часов не меняют. Ниже показаны пары и ошибки в секундах.
- [Синхронность и относительная интенсивность](signals-preview.html) — отдельные
  детекторы, сравнение со случайными сдвигами валидаторов и статистики2/3/5/10секунд.
- [Контракт последнего сопоставления](artifacts/anchor-matching-report.md).
- [Слабые сигналы, контроли и исправление трактовки конечной](artifacts/small-stops-report.md).
- [Полный временной диапазон рейса](artifacts/full-runs-report.md).

Самостоятельные HTML загружают D3 7.9.0 с jsdelivr; нужен доступ к CDN. Данные
встроены в файлы, API и сервер приложения не нужны. Остальные HTML в `artifacts/`
— исходные фрагменты визуализаций; для самостоятельного просмотра используйте
две ссылки выше. Старые графики сохранены как история эксперимента, не как
актуальная инструкция по разметке.

## Последняя логика

1. Сохраняем выбранную гипотезу рейса и сильные начала. Первое начало в окне —
   граничная гипотеза, а не доказанное начало реального рейса.
2. После сильного начала ожидаемое время следующей остановки равно фактическому
   времени этого начала плюс сумме интервалов расписания. Ошибка предыдущего
   перегона дальше не накапливается. Слабые начала не корректируют сдвиг.
3. Малые группы ищем относительно локального фона и по совместной активности
   валидаторов, а не по одному абсолютному порогу числа оплат. Источник кандидатов
   и параметры перечислены в отчёте о слабых сигналах.
4. Среди допустимых слабых пар максимизируем количество совпадений, затем
   минимизируем сумму абсолютных ошибок времени. Сохраняем порядок, уникальность
   остановок и максимум одну пару для перекрывающейся волны оплат.
5. Допуск15/30/45/60/90секунд меняет только слабые пары. Выбранные сильные позиции
   и ожидаемые времена при этом остаются неизменными.

Сравнение на трёх группах за15.05.2025, Europe/Moscow:

| Маршрут | Слабые пары ±30с | Слабые пары ±60с |
|---|---:|---:|
|17|3|7|
|12|4|7|
|11|5|9|

Это полнота условного сопоставления, не точность stop_id. Максимизация совпадений
с расписанием сама по себе не является независимой валидацией.

## Существенные исправления предыдущих выводов

- Первые графики ограничивали анализ30минутами и8началами. Для целого рейса такой
  проверки недостаточно; последующие графики показывают полный ожидаемый путь и
  ещё10минут записей после расчётной конечной, а также всю дневную сессию.
- На конечной может быть только высадка, поэтому отсутствие оплат не опровергает
  прибытие. Последняя наблюдаемая посадка не означает конец движения трамвая.
  Принудительный всплеск на конечной не добавляется, штраф за его отсутствие
  не вводится. Поздние пики могут относиться уже к обратному рейсу.
- GTFS имеет времена, календарь и trip_id, но историческое выполнение именно
  этих рейсов не доказано. Происхождение расписания подробно описано в предыдущем
  аудите. Группировка валидаторов в вагон также остаётся предположением источника.
- Слабые события могут быть хвостом посадки или случайной активностью. Случайные
  контроли поддерживают наличие совместных всплесков, но не подтверждают названия
  остановок. Выход пассажиров и заполненность салона по этим оплатам не измеряются.

## Воспроизведение сохранённых результатов

Без сырого датасета, из корня репозитория:

```sh
python3 docs/analysis/2026-09-26-boarding-matching/artifacts/build-anchor-matching.py
python3 docs/analysis/2026-09-26-boarding-matching/artifacts/verify-small-stops.py
```

Первый скрипт заново вычисляет15конфигураций сопоставления из сохранённого
`small-stops-data.json`. Второй проверяет108вариантов предыдущего эксперимента:
статистики, порядок, ошибки времени, непересечение поддержек, инвариантность к
сдвигу и хеш результата. Новые зависимости не нужны.

`audit-full-runs.py`, `audit-small-stops.py` и ранние `check_displayed_schedule*.py`
сохранены без изменения как точные скрипты исходных прогонов. Они содержат
абсолютные пути исходного рабочего окружения и не являются переносимыми CLI.
Полный повтор требует приватных date-shards, frozen-детекторов, GTFS и предыдущих
worktree-артефактов; перечень путей находится в начале скриптов. Только локальный
аудит использует исходные события, в Git публикуются агрегаты без идентификаторов.

`*-manifest.json` связывают входы, скрипты и результаты SHA256. Исходные HTML
содержат снимок соответствующих данных: после нового расчёта они автоматически
не обновляются. Для нового эксперимента создавайте новую версию результатов.
