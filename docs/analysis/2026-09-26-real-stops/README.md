# Привязка реальных оплат к остановкам: экспериментальная выборка

Подробное описание формул, параметров, назначения остановок и агрегации потоков: [ALGORITHM.md](ALGORITHM.md).

## Контракт результата

Цель — восстановить вероятные остановки успешных оплат за январь–октябрь 2025
по девяти трамвайным маршрутам. Источник оплат — полный проверенный ledger TASK-063;
ни дубликаты исходных строк, ни неоднозначные назначения молча не удаляются.
Идентификаторы оплат и сессий непрозрачные, исходные идентификаторы пассажиров не экспортируются.

`stop_id` — OSM stop-position node, `direction` — локальное направление внутри
маршрута, `pattern_id` — версия отношения OSM. Эти ключи не являются каноническими
ID backend и требуют явного crosswalk перед публикацией на продуктовую карту.

Историческая версия OSM подтверждает состав опубликованного отношения на момент
редактирования. Она **не подтверждает фактический рейс** и все временные изменения.
Существующий рельсовый граф и большинство координат имеют дату 2026 года; такие
геометрические признаки маркированы. Где рельсового ребра нет, явно записано
расстояние по прямой. Начало и конец последовательности открытые: полночь не
означает конечную остановку. Контекст соседних суток не используется, чтобы
расписание пятницы не приписывалось субботе.

Время каждой оплаты остаётся исходным московским временем. Оплаты одного
согласованного сочетания маршрут/выход/вагон объединяются в гипотезу сессии;
конфликты устройств и вагонов сохраняются, строгие метки при них запрещены.
В пределах сессии близкие оплаты образуют группы с ограничением разрыва и полной
длительности. Затем циклическая модель допускает повторные оплаты на остановке,
пропущенные оплаты между остановками и несколько оборотов. Длинный разрыв
сбрасывает фазу, но не назначает конечную автоматически.

Число поддержанных оплатами и скрытых посещений рассчитывается из пути и сохраняется
для проверки согласованности. Оно не считается независимым доказательством правильности.

## Источники

[sources.json](sources.json) содержит URL, контрольные суммы, даты и объём снимков.
Получены обе последовательности для каждого из девяти маршрутов и 37 полных
снимков опубликованных расписаний: 36 современных (будний/выходной, два направления)
и один архивный для №7 на 29 июля 2025. Всего 1 146 остановочных снимков и 132 054
времени отправления. Это времена по отдельным остановкам, а не таблица рейсов:
одинаковые индексы отправлений между остановками не склеиваются в рейс.

Архив №7 содержит укороченный маршрут до Сокольников. Официальные сообщения
[о введении изменения](https://www.mosmetro.ru/news/details/7319) и
[восстановлении](https://www.mosmetro.ru/news/details/7570) ограничивают его период
10 июля–10 августа включительно. Остальные современные расписания используются
как слабые переносимые предположения, не как расписание 2025 года.

OSM: © OpenStreetMap contributors, ODbL 1.0. Расписания: transport.mos.ru;
открытая лицензия на их повторное распространение не установлена. Сырьё хранится
локально в игнорируемых артефактах; публикация наружу не выполнялась.

## Неопределённость и обучение

- `event_assignments.csv.gz`: каждая успешная оплата, кандидат остановки,
  условная вероятность, устойчивость между сценариями и причина неопределённости.
- `burst_candidates.jsonl.gz`: три альтернативы без перенормировки и остаточный
  вес. При точной симметрии произвольная первая остановка не выдаётся за ответ.
- `stop_hour_soft_counts.csv.gz`: полное распределение массы по остановкам.
  Сумма по маршруту и исходному часу равна числу декодированных оплат; это
  математическое ожидание условной модели, не измеренный пассажиропоток остановки.
- `stop_hour_weak_counts.csv`: только строгие устойчивые слабые метки. Пустая
  строка/отсутствующий ключ не означает нулевой поток. Покрытие частичное.
- `mass_ledger.csv`, `evaluation.json`, `receipt.json`: сохранность исходной массы,
  отказы, ограничения источников и контрольные суммы.
- `journey_hypotheses.json`, `patterns.json`: гипотезы проходов, версии и геометрия.

Строгий фильтр требует posterior не ниже 0.5, совпадения пути в минимум 3 из 4
сценариев, минимум четырёх групп в связном фрагменте, отсутствия конфликтов
идентичности и известных несовместимых вариантов маршрута. Сценарии: скорость
4/5/6 м/с и вариант без расписания. Это устойчивость внутри семейства моделей,
а не вероятность истинности. `real_stop_accuracy=unverified`, `calibrated=false`.
Нельзя оценивать точность модели остановочного потока относительно этих же
восстановленных меток и объявлять её точностью относительно реальности.

Экспорт для обучения разделён по целым дням: январь–июнь — train, июль–август —
development, сентябрь–октябрь — diagnostic. Последний срез не заявлен слепым тестом.
Календарные признаки не используют будущие оплаты. Метки рассчитаны ретроспективно
по целому дню; будущие относительно часа оплаты внутри дня допустимы только для
формирования метки, не как онлайн-признаки. Доступность источников на исторический
момент не доказана: `point_in_time_sources_verified=false`.

## Проверка устойчивости на реальных оплатах

[sensitivity.json](sensitivity.json) — фиксированные шесть сессий (5 766 оплат),
выбранные по малому/среднему/большому числу событий на №1 15 января и №7 29 июля.
Совпадение кандидата остановки с базовым расчётом по общим событиям:

| Изменение | Совпадение |
| --- | ---: |
| Группировка: разрыв 20 с, длительность 60 с | 44.2% |
| Группировка: разрыв 40 с, длительность 120 с | 48.9% |
| Детерминированное удаление 20% оплат | 46.1% |
| Сдвиг времени для расчёта на ±5 с | 70.3% |

Во всех шести сессиях и вариантах строгих меток нет. Поэтому доля сохранённых
строгих меток не определена (`null`), а не равна 100%. Масса сохранённых событий
проверена для каждого варианта; исходные времена не изменялись в ledger.
Повторный эксперимент дал побайтово одинаковый отчёт. Эти числа измеряют
чувствительность алгоритма, **не точность остановочных меток**.

## Дополнительный запрет по качеству модели

[model-quality.json](model-quality.json) фиксирует смещение при одновременном
использовании точного архивного и переносимого современного расписания на №7
29 июля. Разная ширина и вес ненормированных временных потенциалов могут
предпочитать направление с менее точным источником. Контрольный пример с
одинаковой геометрией и отправлениями даёт 70% против 30% только из-за этой
разницы. Это ошибка допуска в обучение, которую нельзя оправдать названием
«некалиброванная вероятность».

Поэтому все 10 382 оплаты №7 за этот день, включая 17 первоначально устойчивых
кандидатов, **не допускаются в обучение**. Их исходные назначения и веса сохраняются
для исследования. Алгоритмический запрет отделён от официальных транспортных
ограничений и действует даже при экспорте без календаря сообщений.

## Временные изменения движения

[service-notices.json](service-notices.json) содержит 20 официальных сообщений,
включая восстановления. Дополнительная политика экспорта применяет их к маршруту,
дате и исходному часу оплаты. Если ограничение пересекает часть часа, исключается
весь час. У неизвестного конца ограничения нет вымышленной даты восстановления.
Ночные окна до 05:00 и дополнительный час после приблизительного восстановления
27–28 июня — консервативные правила исключения, а не опубликованное расписание.

Восстановления №17 с 19 апреля (с повторным ограничением 26–27 апреля) и №12 с
21 июня снимают соответствующие чрезмерно широкие запреты для мягких целей.
Новые ночные и дневные исключения имеют приоритет. Исходные рассчитанные веса
и запреты сохраняются отдельно; политика не перенормирует массу и не создаёт
новые строгие назначения. Реестр неполон: отсутствие сообщения не доказывает
нормальное движение. `training_eligible` означает разрешение использовать строку
в эксперименте со слабыми целями, а не наличие проверенной истинной остановки.

## Воспроизведение

Из корня рабочей копии с локальными артефактами:

```sh
uv run --package tramflow-ml python -m tramflow_ml.boarding prepare-real \
  --run ../boarding-dataset/ml/artifacts/boarding-2025-reviewed \
  --out ml/artifacts/boarding-date-shards
uv run --package tramflow-ml python -m tramflow_ml.boarding reconstruct \
  --partitions ml/artifacts/boarding-date-shards \
  --histories ml/artifacts/real-sources/osm \
  --graph data/tram_graph.json \
  --timetables ml/artifacts/real-sources/timetables/timetables.json \
  --config docs/analysis/2026-09-26-real-stops/config.json \
  --out ml/artifacts/real-payment-stops-2025-v1 --workers 6
```

Экспорт после успешного завершения полного расчёта:

```sh
uv run --package tramflow-ml python -m tramflow_ml.boarding export-real \
  --run ml/artifacts/real-payment-stops-2025-v1 \
  --out ml/artifacts/real-stop-training-2025-v1 \
  --service-policy docs/analysis/2026-09-26-real-stops/service-notices.json
```

Получаются шесть gzip CSV: `soft_train/development/diagnostic` и
`weak_train/development/diagnostic`, а также manifest с хешами и причинами исключений.
Для эксперимента обязательно отбирать `training_eligible=True`; остальные строки
сохраняют исходную массу только для аудита. Нельзя заменять отсутствующие строгие
счётчики нулями или использовать `expected_count` как измеренную истину при оценке.
В итоговом архиве также есть каталог остановок с координатами, GeoJSON распределений
и дневные версии графов. Геометрия обзорного GeoJSON берётся из последнего доступного
паттерна в периоде; датированную геометрию следует брать из каталога/дневных паттернов.

Готовый каталог вывода не перезаписывается. Незавершённый расчёт возобновляется
только с прежними кодом, конфигурацией и источниками; завершённые дневные части
перепроверяются по SHA-256. Для нового эксперимента нужен новый каталог.
Зависимости, API, БД, frontend и обслуживаемая модель не меняются.
