# Первая валидация, интервалы расписания и проверка остановочных потоков

Версия: `boarding-timing-experiment.v2`. Это сравнение реконструкций, не измерение
точности остановок. База реализации: `eabc2d5`; новая версия не заменяет исходные
оплаты или результаты v1. Успешная валидация остаётся единицей наблюдения.

## Результат: новая версия не подтверждает надёжную остановочную разметку

Обработаны **4,017,177** успешных оплат за 20 дней и 9 маршрутов. Потерь
событий нет, масса сохранена в каждом исходном маршруте/часе. Это парное сравнение
на фиксированном срезе; полный набор v1 из 304 дней не перезаписывался.

| Показатель | Наблюдаемый результат |
| --- | ---: |
| Совпала остановка **и направление** v1/v2 | 338,557 / 4,016,103 = 8.43% |
| Перераспределённая остановочно-часовая мягкая масса | 7.42% |
| Расстояние v2 от равномерной массы по допустимым посещениям маршрута | 6.81% |
| Медиана вероятности выбранного состояния v2 | 2.58% |
| 99-й процентиль вероятности выбранного состояния v2 | 13.36% |
| Прошли проверку интервалы расписания, рёбра × дни | 9,718 / 10,976 |
| Внутренние устойчивые события v2 | 0 |
| Поддержанные опорные профили из плотных последовательностей | 0 |

У индивидуальных назначений низкое совпадение, а мягкие агрегаты меняются умеренно,
потому что вероятности размазаны по многим остановкам. Близость к равномерному
распределению — предупреждение о слабой пространственной информативности,
а не высокая точность. Даже хорошие совпадения времени допускают много разных
начальных положений и цепочек пропусков.

Принятые интервалы расписания имеют значения 60–300 с и получены из **снимков 2026
года**. Это подтверждает внутреннюю согласованность опубликованных часов, но не
их соответствие движению 2025 года. Расписания округлены до минут; нулевой MAD
совпадающих сдвигов не означает секундную точность. Интервалы архивного направления
№7 отклонены из-за повторяющихся часов без идентификаторов рейсов.

Для №11, №12 и №50 абсолютная привязка к часам отключена во все 20 дней из-за
неполного покрытия остановок; для №7 — в 18 из 20. Межостановочные интервалы из
покрытых частей при этом используются. Начальные кандидаты сохраняются, но их
невозможно трактовать как подтверждённую привязку к конкретному отправлению.

### Пропуски и локальное время

| Показатель | v1 | v2 |
| --- | ---: | ---: |
| Медиана абсолютного локального остатка | 22.76 с | 20.00 с |
| 90-й процентиль остатка | 63.81 с | 65.00 с |
| 95-й процентиль остатка | 92.32 с | 100.54 с |
| Доля ненаблюдаемых промежуточных посещений среди переходов по рёбрам | 46.22% | 49.95% |

Медиана немного уменьшилась, хвост ухудшился, доля предполагаемых посещений без
оплат выросла. Остатки относятся к разным выбранным путям и разным определениям
времени группы; это диагностика согласованности, не независимая ошибка времени
прибытия. Оптимизатор сам выбирает путь с подходящими интервалами.

У плотных переходов v2 доля ненаблюдаемых промежуточных посещений
**38.24%**; максимальная цепочка —
**54**. У всего среза максимум —
**62**. Такие крайние цепочки требуют проверки,
а не признания фактическим проездом без остановок. Число посещений вычислено
из гипотезы пути и не является независимым эталоном.

Наборы событий подтверждены хешами. В этой проверке **v2 хуже по всем четырём

81 сессия (низкая/средняя/высокая численность для каждого из 9 маршрутов

### Что сейчас можно оценивать по транспортному графу

| Статистика | Вывод по эксперименту |
| --- | --- |
| Оплаты по маршруту и времени | Наблюдаемая величина; полностью сохраняется |
| Порядок остановок и условная длительность участка | Можно исследовать с указанием источника и исторических ограничений |
| Где алгоритм предполагает пропуски, аномальные интервалы и длинные проходы | Можно вычислять для диагностики; это не наблюдённые пропуски остановок |
| Остановочные ожидаемые оплаты и их чувствительность | Можно показывать как экспериментальные гипотезы, сравнивая версии и равномерный контроль |
| Достоверный рейтинг спроса по конкретным остановкам | Этими результатами не подтверждён |
| Опорные исторические времена из уверенных плотных проходов | На заданных критериях не получены; отложенная MAE не определена |
| Реальная загрузка вагона и поток на перегоне | Не определяются без сведений о посадках/высадках и начальной загрузке |

**Решение: v2 не заменяет v1 и не повышается до достоверной обучающей разметки.**
Реализованная логика дала проверяемый отрицательный результат: расписание позволяет
получить правдоподобные интервалы, но пока не разрешает пространственную фазу.
Следующее содержательное улучшение — более полное историческое расписание с
идентификаторами рейсов либо независимые начальные географические якоря. Просто
ослабить фильтр и обучить времена по собственным назначениям означало бы скрыть
проблему, а не проверить её.

[парная устойчивость](paired-stability.json), [переходы](transition-summary.json),

## Что реализовано по предложению

| Предложение | Реализация v2 |
| --- | --- |
| Брать начало всплеска | Первая оплата группы; среднее оставлено отдельной абляцией |
| Сопоставить начальный всплеск с несколькими отправлениями | Все допустимые позиции сохраняются в решётке; до 8 начальных кандидатов с ближайшим отправлением экспортируются для каждого сегмента |
| Учитывать дальнейший рисунок интервалов | Совместный расчёт пути и полных вероятностей по всей последовательности |
| Брать интервалы из расписания | Проверяемый сдвиг двух последовательностей времён; при отказе явно используется геометрическое приближение |
| Допускать остановки без оплат | Переход через несколько рёбер, сумма их времён, сохранение списка промежуточных остановок |
| Не накапливать ошибку времени | Каждый интервал вычисляется между фактическими началами двух групп; уже было в v1 |
| Проверять пропуски и число посещений | Доля ненаблюдаемых посещений, длины цепочек, распределения остатков, повторяющиеся остановки без наблюдений, срезы по маршрутам/рёбрам/плотности |
| Использовать плотные последовательности как опору | Обучение устойчивых медианных профилей только на ранних днях и достаточно уверенных соседних назначениях; независимые по времени и вагону проверки |
| Сравнить с прежней версией | Те же исходные оплаты, совпадение stop/direction, перераспределённая полная вероятностная масса, пространственные CSV/GeoJSON |

Номер маршрута и вагона берётся из оплаты. Начальная гипотеза касается положения,
направления и близкого отправления; первый наблюдаемый всплеск не объявляется
выездом с конечной. Поле `trip_id=null`: отдельные времена остановок не дают
подтверждённого общего идентификатора рейса.

## Как проверяются интервалы расписаний

Для каждого соседнего ребра сравниваются две последовательности отправлений.
Для кандидата сдвига выполняется сопоставление один к одному с сохранением порядка,
допускающее отсутствующие отправления. Рассматриваются копии часов соседних суток;
это периодическое сопоставление времени суток, не восстановление даты рейса.

Допуски v2: не менее 8 пар, покрытие не менее 65% от большей последовательности,
разброс совпадения ±30 с, согласованность обеих временных половин списка. Другой
сдвиг, отделённый больше чем на 60 с и набравший не менее 90% поддержки лучшего,
приводит к отказу из-за неоднозначности. Повторяющиеся одинаковые часы без разных
идентификаторов рейса также приводят к отказу.

По расстоянию `L` ограничиваются возможные длительности:
`max(15, L/18) … min(1800, max(180, L/1.2 + 120))` секунд. Эти границы — эвристика,
а не измеренные ограничения движения. Они могут исключить альтернативный сдвиг;
поэтому принятое соответствие не становится доказанным рейсом.

На конечных, границах несовместимых источников и при отсутствии допустимых часов
интервал из расписания не назначается. Явная резервная оценка:
`L/5 + 20 + 120×terminal_after` секунд. Принятые интервалы расписания — разности
времён **отправлений**, а наблюдения — начала **валидаций**. Разница стоянок и
задержек оплаты остаётся шумом; постоянные 15 с не оценивают индивидуальную задержку.

Временное свидетельство остановки теперь использует одинаковые ширину 180 с
и вес 0.2 для всех источников. Это устраняет конкретный перекос v1 от разных
параметров точного и переносимого расписания. Более частые отправления всё ещё
могут давать больше временной поддержки; калибровки на истинных остановках нет.

Все пороги фиксированы до основного сравнения, а не подбирались ради совпадения
с v1. Код и источники привязаны к запуску SHA-256.

## Плотные последовательности и защита от самоподтверждения

Плотный переход имеет минимум 3 события на каждом конце. Для обучения профиля
дополнительно нужны соседние посещения, уверенность ≥0.5, совпадение ≥3/4 сценариев,
однозначные состояния, достаточная длина сегмента, отсутствие конфликтов,
неподдержанных вариантов движения, аномальной неподвижности и чувствительности
к пределу поиска. Время перехода ограничивается по локальному остатку.

Для ребра требуются минимум 5 наблюдений, 2 разных дня и 2 вагона. Оценка — медиана
с удалением выбросов за `max(30 с, 3×1.4826×MAD)`. Эти критерии не делают исходные
назначения истинными. Они препятствуют обучению по единичной удобной гипотезе.

Обучение профилей использует только даты до 1 июля 2025. Проверка — более поздние
даты и вагоны, не участвовавшие даже в отборе кандидатов для обучения. Назначения
остановок при этой проверке фиксированы до применения профиля; неудобные остатки
на проверке не удаляются. Отсутствие поддержки возвращает пустой профиль и `null`
для недоступных метрик, а не искусственное улучшение.

Четыре основных сценария: номинальные локальные времена, увеличение их на 25%,
уменьшение до 5/6 и вариант без часового расписания. Масштабируется полная
длительность ребра, включая стоянку; это анализ чувствительности длительностей.
Мягкая масса берётся из основного сценария, без усреднения четырёх моделей.

## Дизайн сравнения

Основной срез: 15-е и 18-е число каждого месяца с января по октябрь 2025,
20 дат × 9 маршрутов. Обработаны все успешные оплаты выбранных дат, без отбора
только удачно сопоставленных сессий. Это не полный перерасчёт 304 дней.
Фиксированный календарный срез не является случайной репрезентативной выборкой
и не даёт доверительного интервала для всей совокупности.

Для тех же событий v1 читается из сохранённого полного расчёта. Проверяются
идентификаторы, маршрут, исходное время и полная масса по каждому исходному часу.
Нулевые/неопределённые кандидаты выделены отдельно и не скрываются в знаменателе.

Перераспределённая масса — `0.5 × Σ|C_v2−C_v1|`. При одинаковой общей массе она
показывает, какую долю пришлось бы перенести между пространственными ячейками,
чтобы получить другую реконструкцию. Совпадение кандидата и корреляция счётчиков
не являются точностью относительно реального потока.

Дополнительные абляции: среднее вместо первой оплаты, только геометрические
интервалы, отсутствие часов расписания, пороги группировки 20/60 и 40/120 секунд,
удаление 20% событий, временной шум ±5 секунд. Отдельное парное сравнение v1/v2
использует идентичные шесть сессий и возмущения.

## Воспроизведение и файлы

Из корня рабочей копии, после установки зависимостей из lock:

```sh
python -m tramflow_ml.boarding.timing_experiment \
  --source ../boarding-real-alignment/ml/artifacts \
  --out ml/artifacts/timing-v2-comparison --workers 4
python -m tramflow_ml.boarding.timing_sensitivity \
  --source ../boarding-real-alignment/ml/artifacts \
  --out ml/artifacts/timing-v2-sensitivity.json \
  --profiles ml/artifacts/timing-v2-comparison/dense_profiles.json
python scripts/report_timing_v2.py \
  --source ../boarding-real-alignment/ml/artifacts \
  --run ml/artifacts/timing-v2-comparison \
  --out ml/artifacts/timing-v2-report
```

Дневные файлы: назначения оплат, полная мягкая часовая масса, переходы со списками
ненаблюдаемых остановок, начальные кандидаты отправлений, аудит каждого ребра
расписания, итог сравнения и контрольные суммы. Итоговые файлы: обученные профили,
отложенная проверка, статистика переходов, сравнение остановок и GeoJSON.

`training_eligible=false` у всех новых событий: это исследовательское сравнение,
а не автоматически допущенная новая обучающая выборка. Транспортные исключения
из v1 не объявляются исправленными новой моделью времени. На продуктовую карту
и в serving данные не публикуются. Координаты обзорного GeoJSON преимущественно
современные, ключи остановок OSM требуют crosswalk для backend.

## Источники методов и ограничения переноса

- [GTFS Schedule Reference](https://gtfs.org/documentation/schedule/reference/#stop_timestxt):
  связь остановочных времён через идентификатор рейса; такого ключа у наших снимков нет.
- [Forecasting: Principles and Practice](https://otexts.com/fpp3/tscv.html):
  проверка по будущим наблюдениям; здесь применена к оценкам интервалов, а не к
  доказательству остановочной точности.
- [NIST: MAD](https://itl.nist.gov/div898/software/dataplot/refman2/auxillar/mad.htm):
  устойчивая мера разброса; конкретные пороги допуска в этом эксперименте эвристические.

Предыдущая версия и источники: [отчёт v1](../2026-09-26-real-stops/README.md).
