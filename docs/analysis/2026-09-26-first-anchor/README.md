# Первая оплата как обязательная опорная метка

По запросу пользователя первая фактическая оплата становится обязательным первым
кандидатом посадки независимо от порога детектора. Это правило применяется к
наблюдаемому отрезку; начало рейса и номер остановки из него не следуют.
Физическое открытие дверей могло произойти раньше оплаты. Точность остановок
по этому правилу не измерена: нет независимых фактических остановочных меток.

## Контракт

`coalesce(..., first_observation_anchor=True)` вставляет минимум времени оплат,
если его нет среди кандидатов. Затем действует прежнее объединение внутри одной
адаптивной области с запретом объединения через необычную паузу. Сохраняются все
исходные члены групп. Нет фиксированного запрета близких остановок. Без общей
области кандидаты остаются раздельными: универсальная защита от дробления волн
этим изменением не решается.

Для каждого непустого отрезка первый результат равен первой оплате; повторное
применение не добавляет дубликат. `anchor` хранит время, основание и факт вставки;
`trip_start_confirmed=false`, `route_stop_index=null`. Первые пустые остановки
по-прежнему допускаются перебором начальной позиции сопоставления. Метки не
становятся подтверждёнными целевыми значениями для обучения.

Исходные детекторы и версия без опорной метки сохранены. В аудите новая версия
включается флагом `--first-anchor`; на графике выбрана по умолчанию и отмечена
ромбом. Сопоставление всей последовательности с интервалами расписания рассчитано
заново. Raw показывает исходные кандидаты без нового правила и объединения.
Столбик 30 секунд может начинаться раньше метки: он содержит оплаты за весь бин,
тогда как линия стоит на точном времени первой оплаты, не на границе бина.

## Реальные данные

Те же 320 контрольных окон мая–октября 2025, 54 142 оплаты, Europe/Moscow.
Параметры детекторов обучены/откалиброваны только на январе–апреле. Хеши исходных
окон, кандидатов и порогов проверены. Это 30-минутные окна, не доказанные рейсы.

| Метод | Исходные кандидаты | Вставлено опорных меток | Объединено | Результат |
|---|---:|---:|---:|---:|
| Согласие ≥3 семейств | 1952 | 217 | 198 | 1971 |
| Адаптивный поиск | 1894 | 178 | 0 | 2072 |
| GMM | 2203 | 320 | 186 | 2337 |

Проверено 960 сочетаний окно/метод: результат начинается с первой оплаты, баланс
`исходные + вставленные = результат + объединённые` выполнен. Устранение пропуска
первого наблюдения не является измерением полноты остальных остановок.

В примере маршрута 17, 15.05.2025 07:50–08:20, добавлена 07:51:43 — начало
15 оплат на шести валидаторах до 07:51:58. Следующая метка 07:53:42:
интервал 119 секунд против 120 секунд выбранного варианта расписания.
По всей последовательности MAE 19 секунд, контроль с перемешанными перегонами
14,9 секунды; 33 почти равнозначные начальные позиции. Поэтому хорошее совпадение
первого интервала НЕ подтверждает найденные названия остановок или рейс.
Для маршрутов 12 и 11 первые метки 08:10:00 и 13:11:47 соответственно.
