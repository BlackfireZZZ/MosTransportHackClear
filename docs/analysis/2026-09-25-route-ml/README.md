# CatBoost и проверка подключения маршрутного прогноза

На реальных labels проверены 24 фиксированных варианта × 3 временных среза.
Победитель по суммарной ошибке среди прошедших порог: **cat_native**, CatBoost 1.2.10,
MAE, 800 деревьев, depth8, learning_rate0.06, seed42, 4 потока. Признаки: маршрут,
час, день недели, тип дня, июль/август, праздник. Категории переданы нативно, но
one_hot_max_size24 покрывает их кардинальности: выигрыш нельзя приписывать target encoding.

## Измеренное качество

Score = max(0, 1 − WAPE), выше лучше; WAPE считается по общей сумме ошибок/факта,
не средним маршрутных процентов. Прогноз каждого среза сразу на 61 день, без
подглядывания в промежуточные факты и без early stopping по проверяемому будущему.

| Вариант | Апрель–май | Июнь–июль | Август–сентябрь | Октябрь, прогноз от 1 сентября |
|---|---:|---:|---:|---:|
| Последняя неделя | .783474 | .761602 | .780640 | .813883 |
| Среднее 4 недель | .811799 | **.805483** | .802354 | .777234 |
| Тип дня, 4 недели | .846710 | .801810 | .803060 | .775658 |
| CatBoost выбранный | **.859343** | .792905 | **.865402** | **.866016** |

Октябрь: WAPE 18.6117% → 13.3984%, снижение ошибки на 28.01%; score +.052133.
Суммарный development score CatBoost .840430. Он улучшает недельный baseline на
каждом срезе минимум на .031303, но проигрывает более сильному простому baseline
в июне. Это измеренное улучшение, не обещание качества ноября–декабря.

Полные результаты, маршрутные/пиковые/горизонтные срезы, конфигурации и версии:
[development.json](development.json), [зафиксированный выбор](selection.json),
[confirmation.json](confirmation.json). Отбор заморожен до запуска confirmation.
Сентябрь уже использован августовским development; только октябрь (индексы30:61,
дни прогноза31–61) проверяет выбор после отбора. Октябрьский baseline ранее изучался
в EDA: это не слепой holdout. На полном диагностическом сентябрь–октябрь срезе
score .867563; слабее всего маршрут50 (.732692), затем7 (.833657) и25 (.838280).
Маршрут5 не имеет положительной истории: прогноз0, WAPE не определён, не «идеальная модель».

## Что дали эксперименты с признаками

Сравнены недельные/четырёхнедельные профили, тип дня, медиана, HistGradientBoosting,
CatBoost MAE/RMSE, глубина, окна затухания30/60/120 дней, калибровка, смешивание с
профилем, календарь без летнего индикатора, только weekday, CTR и исторические
отношения/уровни. Полный перечень24 конфигураций сохранён в development.json.

Богатые исторические профили и отношения хуже переносятся на следующий сезон:
например cat_full в августе score около .754 против .865 у выбранного календарного
варианта. RMSE сильнее в августе, но слабее суммарно. Летний признак полезен на
этих срезах; по одному году нельзя отделить сезонность от изменения сети/спроса.
Переносы выходных взяты из постановления1335, опубликованного до экспериментов:
[Правительство РФ](https://government.ru/docs/52895/).

## Данные и ограничения

Использованы организаторские labels январь–октябрь, 304×10×24=72960 ключей.
Пропуски заполнены нулём успешных валидаций в выгрузке; полнота поставки неизвестна.
Только события до origin; mutation-тесты проверяют отсутствие влияния будущих labels.
Московское время, календарь2025. Ноябрьский хвост сырых событий не используется.
source_hash — хеш содержимого двух label-файлов с именами, не хеш всего ZIP.
Нет погоды/рейсов/вместимости/остановочных labels; цель — validations, не заполнение салона.
Интервалы неопределённости пока отсутствуют и представлены null, не выдуманными границами.

## Что готово и как подключать

Модель обучена на всей истории и сохранена в `ml/artifacts/route-ml-2025-cat-native/`:
model.cbm, model.json, history.npz, forecast.json, submission.csv и manifest.json.
14 640 прогнозов на 1 ноября–31 декабря2025, целые неотрицательные значения.
Проверяется точное совпадение предсказаний до/после загрузки модели.
Папка игнорируется Git; артефакт остаётся локально в рабочем дереве эксперимента.

Существующие backend/frontend и старый ML CLI не изменены. Новый CLI
`tramflow-route-ml` работает отдельно. Совместимость проверяется преобразованием
route-hour → существующие ForecastSnapshot/ForecastResponse: день почасово, месяц
посуточно, исходные суммы и версии сохраняются. Это проверка границы схем, не
работающий SQL publisher и не переключение текущего приложения на новую модель.

Следующий шаг подключения: явное сопоставление route number→DB ID, отдельный
route-only publisher с атомарной записью, endpoint smoke test и проверка интерфейса
на validation_count. Направления/остановки/год/позиции транспорта модель не поддерживает.
Действующий stop-based forecast.v1 не ослаблен. См. [ADR0008](../../decisions/0008-experimental-route-model.md).

## Воспроизведение

Из корня репозитория, с исходным ZIP по указанному локальному пути:

```bash
uv sync --all-packages --all-extras --locked
uv run --package tramflow-ml tramflow-route-ml compare --archive '/Users/cute/MosTransport2026Hack/dataset (1).zip' --output /tmp/development.json
uv run --package tramflow-ml tramflow-route-ml compare --archive '/Users/cute/MosTransport2026Hack/dataset (1).zip' --output /tmp/confirmation.json --candidates week1,week4,type4,cat_native --origins 2025-09-01
uv run --package tramflow-ml tramflow-route-ml train --archive '/Users/cute/MosTransport2026Hack/dataset (1).zip' --output /tmp/new-route-model --candidate cat_native
uv run --package tramflow-ml tramflow-route-ml predict --model /tmp/new-route-model --output /tmp/reloaded-forecast.json
```

Train требует новую output-папку и не перезаписывает существующую модель.
Загружать только доверенные локальные bundles; это не защищённый публичный registry.
