# Датасет организатора и формат конкурсной отправки

Источник: `README.md` из [публичного архива организатора `dataset.zip`](https://disk.yandex.ru/d/DiFwlfMOauxjBg), проверен 26.09.2026. Здесь описан предоставленный формат; наличие описания не означает, что адаптеры репозитория уже реализуют каждый его элемент. PDF организатора и уточнения из чата приведены в [постановке задачи](TASK.md). Архив объёмом 2,7 ГБ и записи отдельных пассажирских транзакций хранятся вне Git.

## Целевая величина и разделение данных

Одна посадка — одна успешная валидация (`validation_result == 1`). Конкурсная целевая величина — **число посадок по трамвайному маршруту, календарной дате и часу**. Это не наполненность вагона, число уникальных пассажиров, пара «откуда — куда» или число посадок на остановке.

| Файл | Период и назначение |
|---|---|
| `train.csv` | Сырые валидации за 01.01–31.08.2025; история для обучения. |
| `test.csv` | Сырые валидации за 01.09–31.10.2025; доступная история для проверки и выбора модели. |
| `labels/labels_day_train.csv` | Предоставленные часовые агрегаты целевой величины для `train.csv`. |
| `labels/labels_day_test.csv` | Предоставленные часовые агрегаты целевой величины для `test.csv`. |
| `test_submission.csv` | Полный пример отправки с базовым прогнозом около 0,48 по WAPE-score. |
| `spravochniki/Хакатон_пример_валидаций.xlsx` | Небольшой пример строк валидаций. |
| `spravochniki/Хакатон_справочники_трамвай_10_маршрутов.xlsx` | Справочники маршрутов, остановок, последовательности остановок, расписания и вагонов. |

Скрытый период оценки — **01.11–31.12.2025**, 61 день подряд. Его валидации и целевые значения недоступны. Все 61 день нужно прогнозировать по информации, доступной на 31.10.2025: модель однодневного горизонта не может использовать наблюдения ноября или декабря как лаговые признаки. [Ответ организатора](TASK.md#уточнения-организатора-из-чата) допускает использование предыдущих собственных прогнозов с накоплением ошибки. Имя `test.csv` не означает, что этот файл является скрытой конкурсной выборкой.

### Сырые CSV валидаций

`train.csv` и `test.csv` имеют кодировку UTF-8, разделитель `;` и заголовок:

```text
tran_no;device_no;tran_date_time;begin_date_time;input_date_time;crd_hashcode;validation_result;tran_type_id;place_id;good_type;pass_route;ngpt_route;bus_exit_no;garage_number
```

| Поле | Значение и применение |
|---|---|
| `tran_no` | Идентификатор транзакции. |
| `device_no` | Идентификатор валидатора. |
| `tran_date_time` | Время валидации; его дата и час задают агрегацию целевой величины. |
| `begin_date_time` | Время начала рейса. |
| `input_date_time` | Время загрузки записи; встречаются некорректные и будущие даты, поэтому оно не задаёт время целевой величины. |
| `crd_hashcode` | Псевдонимизированный хеш карты; чувствительные данные отдельного события, не нужные для подсчёта посадок. |
| `validation_result` | `1` означает успешную валидацию; остальные значения не считаются посадками. |
| `tran_type_id` | Тип транзакции; `52` описан как основной тип прохода, но заданный фильтр целевой величины — `validation_result == 1`. |
| `place_id` | Код площадки или депо, **не идентификатор остановки**. |
| `good_type` | Тип билета или тарифа. |
| `pass_route` | Зашумлённое поле цепочки пересадок; не ключ маршрута. |
| `ngpt_route` | Обозначение маршрута, например `25 трамвай`; источник целочисленного `route`. |
| `bus_exit_no` | Номер выхода или наряда вагона. |
| `garage_number` | Парковый номер вагона. |

`README.md` организатора предупреждает о небольшом хвосте следующего месяца в сырых файлах. Фильтровать нужно по `tran_date_time` и нужному периоду, а не по имени файла. В README не указана явная временная зона сырых отметок; перед объединением с контрактом `Europe/Moscow` её нужно подтвердить. Нельзя выводить в журналы, коммитить или помещать в отчёты `crd_hashcode` и идентификаторы отдельных транзакций.

### Предоставленные метки

Оба файла `labels/labels_day_*.csv` используют UTF-8, `;` и заголовок:

```text
route;date;hour;boardings
```

Это агрегаты соответствующих сырых файлов. Некоторые ключи «маршрут — дата — час» могут отсутствовать; отсутствие нужно обрабатывать явно, оно само по себе не доказывает наблюдённый нуль. Перед обучением необходимо сверить заново собранные метки с предоставленными. README организатора называет маршрут `5` разреженным; фактическая проверка покрытия приведена ниже.

**Проверка сырых файлов от 26.09.2026.** Архив с SHA-256 `7e34e56b93f7379cb5abe9aca8e87967cb986111b9939caead5a3fea6c296e5a` содержит 62 443 497 сырых строк. Потоковая агрегация всех успешных валидаций января–октября точно совпала с 57 551 положительным ключом меток и 59 667 191 посадкой. Следовательно, отсутствующие ключи имеют ноль успешных валидаций *в этих предоставленных файлах*; это не доказывает, что вагон работал или сбор данных был полным в каждый такой час. Для маршрута `5` в доступный период нет успешных валидаций (одна октябрьская сырая строка содержит отказ). Хвост из 523 успешных строк 1 сентября в `train.csv` объясняет 15 ранних ключей в тестовых метках; 562 успешные строки 1 ноября в хвосте `test.csv` находятся за пределом доступной информации 31.10.2025. Воспроизводимая команда сверки, привязанная к контрольной сумме, приведена в [ML-инструкции](../../ml/README.md#organizer-route-hour-experiment).

### Конкурсная отправка

В раздел `Data Science` загружается CSV в UTF-8 с разделителем `;` и ровно таким заголовком:

```text
route;date;hour;prediction
```

`route` принимает значения `1, 5, 7, 11, 12, 17, 25, 26, 28, 50`; `date` охватывает все даты с `2025-11-01` по `2025-12-31`; `hour` — целое число от `0` до `23`; `prediction` — конечное неотрицательное число, которое при оценке округляется до целого согласно README датасета. Ключ `(route, date, hour)` уникален, полная декартова сетка содержит **10 × 61 × 24 = 14 640 строк**. `test_submission.csv` задаёт ожидаемую структуру: заменяются значения прогноза, а не ключи. Это отдельная отправка, не выгрузка CSV/XLSX из дашборда, требуемая PDF.

README датасета определяет `WAPE = sum(abs(y - prediction)) / sum(y)` и `WAPE-score = max(0, 1 - WAPE)`. Балльные диапазоны PDF приведены в [постановке](TASK.md#оценка-и-сдача). Локальную проверку проводят на нетронутом хронологическом интервале; публичный балл отправки не доказывает качество остановочного или годового прогноза.

## Справочник и ограничение определения направления

Шесть листов файла `Хакатон_справочники_трамвай_10_маршрутов.xlsx`:

| Лист | Полезные ключи и поля | Ограничение |
|---|---|---|
| `Маршруты GTFS_ROUTES` | `route_id`, `route_short_name`, название, статус и даты действия маршрута | Соединять конкурсный номер маршрута с `route_short_name` после проверки покрытия. |
| `Остановки GTFS_STOPS` | `stop_id`, `stop_name`, `stop_lat`, `stop_lon`, `actual_date`, `is_deleted` | Координаты остановки не означают наблюдаемое место посадки. |
| `Порядок_остановок GTFS_TRIPS_ST` | `route_id`, `trip_id`, `direction_id`, `stop_sequence`, `stop_id`, даты действия | Описывает справочные варианты рейсов, а не направление каждой сырой валидации. |
| `Наряд` | Дата, маршрут/выход, вагон и вместимость | Проверенные строки примера датированы 2026 годом; без временного подтверждения их нельзя соединять с валидациями 2025 года. |
| `Расписание` | `route_id`, `trip_id`, `direction_id`, `grafic`, `stop_id`, время прибытия/отправления | Шаблон расписания не определяет направление конкретной исторической валидации. |
| `Порядок_с_координатами` | Вариант рейса и упорядоченные остановки с названиями и координатами | Пригоден для карты после проверки идентичности и дат действия. |

По README датасета справочные маршруты пересекаются с маршрутами валидаций только для `{1, 5, 7, 11, 12}`. Основная оценка строится по маршруту и часу. Организатор [прямо ответил в чате](TASK.md#уточнения-организатора-из-чата), что по данным нельзя определить направление трамвая на данном маршруте. Для графовой концепции команды направление остаётся **оценкой с указанным происхождением**, согласованной с маршрутным итогом и проверяемой отдельно; см. [CONCEPT.md](CONCEPT.md#direction-and-observability) и [ADR-0006](../decisions/0006-stop-identity-and-direction.md).

## Первичные проверки данных

1. Записать контрольную сумму архива, ссылку на источник, условия доступа и хранения, локальные суммы файлов без добавления сырых данных в Git.
2. Проверить число строк, диапазон времени, некорректные отметки, покрытие маршрутов, разреженный маршрут `5`, отказы и дубликаты идентификаторов транзакций. Сверить часовые агрегаты по `validation_result == 1` с предоставленными метками.
3. До изменения адаптеров зафиксировать временную зону, разбор номера маршрута, правила для отсутствующих ключей и дубликатов. Сохранить хронологию `train`/`test` и информационный предел 31.10.2025.
4. До отправки проверить сетку из 14 640 ключей, конечность и неотрицательность прогнозов, уникальность вне зависимости от порядка строк, кодировку и разделитель CSV.
