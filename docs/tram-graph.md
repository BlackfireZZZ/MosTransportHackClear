# Граф трамвайной сети Москвы

Граф трамвайной сети Москвы с поиском маршрутов построен по данным [Overpass API](overpass-api.md) скриптом [`scripts/fetch_tram_graph.py`](../scripts/fetch_tram_graph.py).

- **Вершины** — места остановки трамвая, ключ — ID узла OSM с тегом `stop_position`.
- **Рёбра** — направленные связи между последовательными остановками хотя бы одного маршрута. Общий участок двух маршрутов представлен одним ребром; все маршруты перечислены в атрибуте `routes`.
- **Длина ребра** измерена **вдоль рельсов**, а не по прямой. В PTv2 узлы `stop_position` лежат на путях, поэтому между остановками суммируются длины последовательных отрезков пути.

## Повторное построение

```bash
python3 scripts/fetch_tram_graph.py --out-dir data
```

Нужен Python 3.13 репозитория; используются только модули стандартной библиотеки. Скрипт и API применяют общие средства проверки и публикации графа из `backend/app/infrastructure/`. Параметры `--area` и `--admin-level` задают другую территорию, `--api-url` — другой экземпляр Overpass API.

Ответ HTTP 200 с любым полем `remark` отклоняется, как и неверный формат данных или ссылки на отсутствующие узлы и пути. Такие ответы не меняют текущую версию. Тесты используют подменённый транспорт и сохранённые данные, без запросов к работающему Overpass.

## Версионная публикация и откат

Новая выгрузка создаёт `data/graph-store/tram_graph.manifest.json` и неизменяемый каталог `data/graph-store/snapshots/<version>/`. Каждый снимок содержит пять файлов из таблицы ниже и собственный манифест. Версия схемы манифеста — 1: `source` хранит общие сведения об извлечении и время источника, `files` сопоставляет пяти фиксированным именам `sha256` и `size_bytes`, а `version` равна SHA-256 канонического тела манифеста без самого поля версии.

До активации должны совпасть значения графа, концы геометрий, метаданные и представления CSV/GraphML. Файлы подготавливаются и синхронизируются до атомарной замены активного манифеста. При первой публикации всё хранилище устанавливается атомарно, чтобы прерванная миграция не отключила старые файлы. Если хранилище уже существует, отсутствие или повреждение манифеста либо файлов приводит к ошибке: читатель не выбирает старые файлы молча. Допущения о локальной файловой системе POSIX и ограничение долговечности финального `fsync` описаны в [ADR-0004](decisions/0004-atomic-graph-snapshots.md).

Прежние настройки `TRAM_GRAPH_JSON`/`TRAM_GRAPH_GEOJSON` и конструктор репозитория продолжают работать. При стандартных именах файлов в одном каталоге API находит `graph-store/`, проверяет хеш каждого файла и загружает один полный снимок. До первой публикации используются прежние плоские файлы в Git. Явно заданные другие имена загружают соответствующую старую пару файлов напрямую. API кэширует первую корректную сеть: после активации снимка процессы API нужно перезапустить. Публичные поля API графа не меняются.

Список сохранённых версий и включение одной из них без обращения к Overpass:

```bash
ls data/graph-store/snapshots
python3 scripts/fetch_tram_graph.py --out-dir data --rollback <version>
```

Откат заново проверяет выбранный набор и меняет манифест; версии не удаляются. Ошибка записи до точки фиксации оставляет предыдущий выбор. Прерванные процессы могут оставить промежуточные каталоги или готовые, но не выбранные снимки; активными они не читаются. Перед ручной очисткой их нужно изучить.

Для чтения активного JSON сторонним инструментом сначала однократно загрузите манифест:

```python
import json
from pathlib import Path

store = Path("data/graph-store")
manifest = json.loads((store / "tram_graph.manifest.json").read_text())
snapshot = store / "snapshots" / manifest["version"]
doc = json.loads((snapshot / "tram_graph.json").read_text())
```

Для проверки контрольных сумм и согласованности представлений используйте `app.infrastructure.graph_artifacts.load_active_graph(Path("data"))` из каталога backend. При прямом чтении файлов проверять заявленные хеши должен сам читатель.

## Файлы

| Файл | Формат | Назначение |
|---|---|---|
| `data/tram_graph.graphml` | GraphML | `networkx.read_graphml`, Gephi, igraph, yEd |
| `data/tram_graph.json` | JSON в формате node-link | `networkx.node_link_graph` или прямое чтение |
| `data/tram_graph.geojson` | GeoJSON | Остановки точками и пути линиями с фактической геометрией на карте |
| `data/tram_stops.csv` | CSV | Табличные редакторы, pandas |
| `data/tram_edges.csv` | CSV | Табличные редакторы, pandas |

Эти пути относятся к сохранённому в Git старому набору. После повторного построения используйте каталог выбранного снимка вместо префикса `data/`: отдельные старые файлы сохраняются и не обновляются.

GraphML и JSON в формате node-link содержат один и тот же граф. GeoJSON дополнительно хранит полную линию пути для каждого ребра, поэтому он в несколько раз больше.

### Атрибуты

Вершина:

| Поле | Тип | Значение |
|---|---|---|
| `id` / ID узла | int | ID узла OSM с тегом `stop_position` |
| `name` | string | Название остановки; при отсутствии — название соседней платформы, затем `node/<id>` |
| `lat`, `lon` | float | Координаты WGS84 |
| `routes` | list / строка через `;` | Обозначения маршрутов с этой остановкой |

Ребро:

| Поле | Тип | Значение |
|---|---|---|
| `source`, `target` | int | ID узлов остановок с заданным направлением |
| `length_m` | float | Длина пути в метрах |
| `routes` | list / строка через `;` | Обозначения маршрутов на участке |

Источник, лицензия, территория, время выгрузки OSM и счётчики извлечения находятся в объекте `metadata` файлов JSON и GeoJSON и элементе `<desc>` файла GraphML.

## Пример чтения

```python
import networkx as nx

G = nx.read_graphml("data/tram_graph.graphml")
print(G.number_of_nodes(), G.number_of_edges())   # 856 919

# Кратчайший путь по длине рельсов
path = nx.shortest_path(G, source="1377188043", target="472373305", weight="length_m")
metres = sum(float(G[a][b]["length_m"]) for a, b in zip(path, path[1:]))
print(len(path), round(metres / 1000, 2))         # 77 32.01
# Даниловская мануфактура -> Стадион «Труд» -> ... -> Курский вокзал
```

В GraphML ID узлов — строки, в JSON node-link — целые числа:

```python
import json, networkx as nx

doc = json.load(open("data/tram_graph.json"))
G = nx.node_link_graph(doc, edges="links")
# Данные ребра: {"length_m": 511.2, "routes": ["2", "4", "32"]}
```

Оба примера запускались на сохранённых файлах с networkx 3.6.1. Нужен аргумент `edges="links"`: без него networkx 3.x ищет ключ `edges` и возвращает пустой граф.

Для использования JSON без networkx достаточно преобразовать список связей в список соседей выбранной графовой библиотеки.

| Остановки | 856 |
| Рёбра | 919 уникальных, 2102 участков по маршрутам |
| Общая длина путей | 377 км |

### Две компоненты связности

Если не учитывать направление рёбер, граф разделяется на компоненты с 694 и 162 остановками: между ними нет рельсового соединения. Это не ошибка извлечения: северная сеть вокруг Тимирязевской, Большой Академической и улицы Костякова (маршруты 6, 10, 15, 21, 23, 27, 28, 29, 30, 31) физически отделена от остальной сети Москвы. **Поиск пути должен обрабатывать недостижимый пункт назначения.**

### Другие особенности

- Степени вершин: 665 промежуточных остановок, 136 развилок, 40 конечных и 15 вершин степени 4.
- Рёбра направленные. Пара *физических* остановок, обслуживаемая в обе стороны, представлена двумя рёбрами между **разными** ID узлов — по одному на направление. Длины могут различаться, если пути не параллельны. Между одной парой ID нет рёбер в обе стороны: в выгрузке 0 обратных рёбер, поэтому ID узла уже связан с направлением движения. Последствия для единого пространства идентификаторов описаны в [ADR-0006](decisions/0006-stop-identity-and-direction.md).
- У 10 остановок нет названия в OSM; используется `node/<id>`. Это существующие остановки без названия в источнике.
- Обозначения маршрутов бывают нечисловыми: `А`, `1а`, `39а`, `47а`, `т1`, `т2`. Сравнивать и сортировать их следует как строки.
- Одно физическое место остановки может быть представлено двумя узлами, по одному на направление, с разными ID и близкими координатами. Для представления физической остановки вместо точки остановки необходимо объединение по названию и близости.

## Проверка в репозитории

[Тесты API графа](../backend/tests/test_tram_graph_api.py) сверяют число вершин, рёбер, длину и размеры компонент с сохранённым [JSON](../data/tram_graph.json), а также проверяют поиск маршрута и GeoJSON. [API](../backend/app/api/routes/tram_graph.py) предоставляет `/api/v1/tram-graph/stats`, `/routes`, `/stops`, `/edges`, `/geojson` и `/path`. Это проверка графового справочника; она не подтверждает место посадки отдельного пассажира и не входит в оценку маршрутно-часового прогноза.
